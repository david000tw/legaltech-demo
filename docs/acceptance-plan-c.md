執行環境：開發者本機。AI 用本機 Claude Code（訂閱方案）。資料庫是開發資料庫，已升到 migration 0012，並匯入 2025～2027 年行事曆。
資料：全部是合成案件，沒有任何真實案件資料。唯一的外部連線是向司法院判決書系統下載公開判決 PDF。

## 結論

設計 6.3 的九個驗收步驟都在瀏覽器實際操作過，並依設計得到預期結果。

驗收過程沒有發現新的產品問題。後端完成後，審查者另外找到 4 個問題，都已修正，並各補一個自動化測試：

1. 兩人同時把判決插入同一段時，會漏掉其中一個標記。
2. 期間很長時，行事曆讀取範圍不夠。
3. migration 寫死了判決庫帳號的密碼。
4. 判決庫已有的判決，還是會再向司法院下載一次。

有一些地方要請合作律師審定：期限規則、在途期間、補行上班日、裁判費尾數、繕本份數的算法，見第 6 節。

## 6. 待合作律師審定

1. **期限規則**：
   - 屆滿日＝生效日＋期間＋在途期間，期間自生效翌日起算；
   - 只有期間末日遇假日才順延；
   - 本人與訴訟代理人都有送達時，取生效日較早者。
2. **在途期間**：
   - 系統不內建在途期間表，由律師依「法院訴訟當事人在途期間標準」填天數；
   - 勾選「訴訟代理人住居法院所在地」時算 0 日。
3. **補行上班日**：照行政機關辦公日曆，補行上班的星期六算上班日、不順延。
4. **裁判費尾數**：0.5 元四捨五入，見第 4 節；逾 1,000 萬元的級距也待確認。
5. **繕本份數**：法院 1 份＋他造各 1 份＋留存 1 份。「他造」＝角色和我方第一位當事人不同的人，包括立場相同但列為被告的人。
