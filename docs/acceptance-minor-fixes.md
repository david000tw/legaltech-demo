## 修正方式

三組平行修（各自 worktree、各自測試資料庫），合併後由審查員看整個分支（REVISE），再修審查員的 11 點。每項都先寫會失敗的測試。

審查員找到、已修：
- 草稿頁讀取依段落順序寫引用，和其他寫入者（先鎖段落再寫引用）順序相反 → 讀取先鎖草稿、再依 id 鎖全部段落。
- 段落鎖住後新增支持度檢查列（外鍵指向案件，要對案件列取 KEY SHARE），與先鎖案件的辨識修正互等 → 案件列一律鎖成 FOR NO KEY UPDATE（`app/db.py` 的 `CASE_LOCK`），案件鎖之間照樣互斥。
- 草稿頁輪詢沒有「上一次還沒回來就跳過」→ 加上。
- 「一、二審判決」標題被去掉「一、」→ 頓號後緊接中文數字不算編號。
- 複製輪次後大事記誤報需要重新整理 → 只看去重後的同一批來源。
- 健檢把本案案號、卷證裡的程序案號標成不在清單；字號對回候選時沒帶法院 → 略過並帶上法院。
- 辨識完成時面板重建，打到一半的內容不見 → 改成原地重讀。
- 「同一判決引文不一致」也用在卷證、法條 → 改「同一引用的引文不一致」。
- 表單型 Word 的文字在內容控制項裡讀不到，又被新規則擋成 422 → 讀進內容控制項。
- 「損害包括㈠所述醫療費用」不再被當段落參照 → 「包括」後面同一句還有「、(二)」才算列舉。
- 開發環境不小心啟動第二個後端，會把正在跑的辨識標成中斷 → 寫進 `docs/deploy-notes.md`。

另外修正：計畫 2A 改只用 AI 時把一個校對員模式的併發測試改錯參數（`test_concurrent_correction_and_proof_write`），先前報告的「全部通過」其實少這一個；已改正。

## 延後的小問題

- 同一引用的引文不一致標記：律師改了同段其他文字（或插入釘選）後標記會消失，只剩第一段引文；仍要重新審核，不會漏擋。
- `ExportButton.tsx` 多一個熱更新 lint 警告。
- `patch_claim`、`delete_claim` 改請求項目依據時沒鎖案件列，與辨識修正視窗仍有競爭（`confirm_claim` 已修）。
- 輪次頁輪詢（`GET /rounds/{id}`）的對造書狀檢查仍逐頁查詢，300 頁的案件會慢。
- 「檢查漏列日期」沒有上限，日期上千時清單很長。
- 大事記「需要重新整理」用工作開始時間（程式時鐘）比資料庫時間；同一台主機沒問題。
