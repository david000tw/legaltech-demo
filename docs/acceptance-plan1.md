# 計畫 1 驗收報告（核心流程）

日期：2026-11-23
執行環境：開發者本機，AI 使用本機 Claude Code（訂閱方案，模型 opus），資料庫為獨立的測試資料庫 `legaltech_test_e2e`。
資料：全部為合成案件，沒有任何真實案件資料。

## 結論

3 件合成案件都能從「上傳對造書狀」跑到「可審核的書狀草稿」，所有引用都通過系統驗證。紅隊案件裡藏的假判決指令，AI 沒有照做。瀏覽器實際操作「審核 → 匯出 Word → 改原證號 → 自動退回未審、匯出被擋」整條流程，結果都符合預期。

## 2. 瀏覽器實際操作（Playwright）

| 步驟 | 結果 |
|---|---|
| 以 `lawyer@e2e.test` 登入 | 成功，進入案件列表，看到 3 件案件 |
| 開 demo-lin → 開草稿 | 9 段草稿、「匯出 Word」按鈕停用，上方列出待辦 |
| 點判決引用 J10 | 左側顯示判決原文，被引用的那句以黃底標出 |
| 逐筆按「已讀原文，確認」（8 筆） | 每按一筆，該筆待辦就消失 |
| 逐段按「標記已審」（9 段） | 每段顯示「已審（(110)北律字第0001號）」，匯出按鈕變成可按 |
| 按「匯出 Word」 | 下載 `民事準備書狀.docx`：25 段、沒有殘留引用標記、文末有證物清單；資料庫多一筆匯出紀錄（只存雜湊值） |
| 把「原證3」改成「原證6」 | 引用原證3 的第 5～8 段自動退回「未審」，內文改顯示「原證6」；其他 5 段維持已審 |
| 再匯出 | 按鈕停用；直接呼叫後端也回 409，列出第 5～8 段「段落尚未審核」 |

驗收過程中發現前端沒有「改原證號」的操作介面（後端功能已有），已補上（案件頁每個卷證旁的「改號」按鈕），並加了前端測試。

## 4. 觀察到、留給後續計畫的事

- 草稿裡卷證出處直接接在引號後面（例：「…發生碰撞。」原證1第1頁。），沒有括號，讀起來不順。可在顯示時改成「（原證1第1頁）」。
- tc-3946 的事實改寫自臺中地院 113 年度中簡字第 3946 號判決，AI 又引用了同一份判決的段落。合成案件才會這樣，真實案件不會發生，但測試案件之後可以換一份來源。
- 同一份判決的不同段落會以不同代碼（J7、J10、J17）出現，律師要分別確認。之後可考慮同一份判決只確認一次。
